# Physics PPT Toolkit 产品需求与工程路线图

版本：v1.1<br>
状态：主规划 / 单一事实源<br>
适用范围：Windows + Microsoft PowerPoint 下的既有初中物理 PPTX/PPTM 课件<br>
更新时间：2026-09-10

## 1. 文档用途

本文统一定义产品定位、需求边界、默认样式、目标架构、迁移路线、验收门禁和任务清单，是后续人工开发与 AI 编码的主依据。

其他文档分工：

- `初中物理PPT统一排版规范.md`：详细样式规则。
- `自动化边界与风险控制.md`：写回风险和回滚原则。
- `使用方法.md`：最终用户操作说明。
- 公式、媒体路线图：非默认实验链路。
- `公式识别转换实施计划.md`：公式载体识别、FormulaIR、模型评测、受控写回和 AI 编码任务卡。

发生范围或优先级冲突时，以本文的默认主线为准。实验功能不得反向扩大默认工作流。

## 2. 产品定位

### 2.1 一句话定位

面向初中物理既有课件的本地、离线、低风险样式规范化与视觉验收工具。

### 2.2 核心价值

在不改变教学内容和页面结构的前提下，批量发现并修正字体、字号、颜色、字重、背景、边框等确定性样式问题，生成不覆盖原件、可验证、可回滚的课堂使用副本。

### 2.3 目标用户与场景

- 整理历史课件的初中物理教师。
- 统一备课组课件样式的教师或管理员。
- 批量检查 PPTX 可读性和样式一致性的维护者。

典型流程：输入 PPTX/目录 → 自检和只读检查 → 生成规范化副本 → PowerPoint 导出验证 → 规则与宿主 AI 视觉审查 → 报告和交付。

## 3. 需求边界

### 3.1 默认主线必须做

- 检查和规范化字体、字号、字体颜色、字重。
- 检查页面背景、简单文本框填充、边框和非必要装饰效果。
- 检查小字号、文本溢出、异常换行、对象越界和渲染异常。
- 保存新文件或新目录，不覆盖输入文件。
- 输出结构化报告、`summary.md` 和 `review-manifest.json`。
- 用 PowerPoint 实际打开和导出验证最终副本。
- 对处理前后不可变属性进行自动比较。
- 支持宿主 AI 对逐页渲染图做只读视觉审查。

### 3.2 默认主线明确不做

- 不按教学意图分类页面。
- 不分析、改写、补充或删除教学内容。
- 不拆页、删页、增页或改变页面顺序。
- 不移动、缩放、旋转、裁剪、组合或拆分对象。
- 不改变对象层级和对象数量。
- 默认不修改动画、触发器、切换效果、速度、自动计时或鼠标单击换片行为；仅在显式启用防误触模式时，允许全部页面将 `AdvanceOnClick` 从 `true` 改为 `false`。
- 不处理视频、音频的编码、压缩、字幕或播放兼容性。
- 不默认处理 OCR、AI 清晰化或联网视觉 API。
- 不默认把文本或图片公式转换为 LaTeX、SVG、MathML 或 OMML。
- 不自动修复物理图像、光路图、电路图、受力图和实验示意图。
- 不建设 WPF、Web 服务、数据库、插件市场或复杂审核平台。

### 3.3 非默认实验功能

以下能力可保留现有代码和显式参数，但不得出现在默认入口，不作为主路线新增投入：

- 白名单文本公式转 OfficeMath/OMML。
- LaTeX/MathJax 到 SVG 的展示兜底。
- 图片公式 OCR、图片 AI 清晰化。
- 媒体压缩或格式优化。
- 自动视觉修复副本。

公式实验能力必须继续保持以下分层，不得把“全部对象都有处理结论”误写成“全部对象都成功转换”：

| 模式 | 允许的写回 | 默认状态 | 适用范围 |
|---|---|---|---|
| `ReportOnly` | 不写回 | 默认 | 盘点载体、生成候选、输出证据 |
| `CandidateOnly` | 不写回 | 默认实验前置 | OCR/模型输出进入 FormulaIR 候选 |
| `ClosedWorldUnattended` | 只写白名单或受控语法的已验证项 | 显式开启 | 可取消逐条人工确认，但不取消机器门禁 |
| `ReviewRequired` | 不写回 | 降级状态 | 未知、低置信度、复杂或语义有歧义项 |
| `ExplicitMigration` | 仅针对用户指定的迁移批次 | 显式开启 | MathType/OLE 或兼容性专项迁移 |

`ClosedWorldUnattended` 只表示无人逐条点击确认，不表示 AI 可以直接决定教学内容。任何未命中白名单、无法通过 FormulaIR 规范化或无法通过结构/宿主/视觉门禁的对象，都必须保留原状并报告。

实验功能必须显式开启、独立输出、独立报告，失败不影响主流程，且不得覆盖任何上游 PPTX。

## 4. 产品原则

安全优先级：

```text
不改变教学内容
  > 不改变页面结构和讲授行为
  > 课堂可视性
  > 兼容性
  > 样式一致性
  > 美观增强
```

- 样式统一与内容完整、对象几何或讲授行为冲突时，保留原状并报告。
- 优先修正已有安全契约冲突，不先增加功能。
- 没有真实样本和可观测证据时，不新增自动修复规则。
- 现有技术栈能解决时不引入新运行时，不预建通用插件系统。
- 宿主 AI 只作为视觉审查门禁，不直接写回 PPTX。
- 公式自动化的信任锚点是版本化的 canonical FormulaIR/白名单，不是 OCR 字符串、模型置信度或 VLM 自评。
- “全量”首先要求每个公式对象有 `Converted`、`FallbackSvg`、`OriginalKept`、`ManualRequired` 或 `Skipped` 之一的明确归宿；不把转换覆盖率当作唯一成功标准。
- 图片、MathType 和普通文本公式必须先分类，不能通过同一条无差别替换路径处理。
- 单文件失败不得让其他文件无报告地中止；写回失败不得把半成品列为成功。

## 5. 默认视觉规范

### 5.1 字体

| 内容 | 默认字体 | 原因 |
|---|---|---|
| 中文 | 微软雅黑 | Windows/Office 教室环境兼容性优先 |
| 英文、数字、单位 | Arial | 普遍可用、投影清晰 |
| 已有 Office 公式 | Cambria Math | PowerPoint 原生公式兼容性优先 |
| 中文公式角标 | 公式专用东亚字体（默认宋体；可配置） | 与 MathType 常见衬线角标更接近；普通中文仍使用微软雅黑 |

- 不默认嵌入大型中文字体。
- 不默认改用思源黑体、Noto Sans CJK 或 STIX Two Math。
- 不强制替换已有 OfficeMath 的公式字体。
- 不使用 Light、ExtraLight、艺术字、手写体或压缩字体作为正文。

### 5.2 字号

| 内容 | 默认值 | 可接受范围 |
|---|---:|---:|
| 章节标题 | 56 pt | 46–56 pt |
| 页面主标题 | 46 pt | 40–48 pt |
| 二级标题 | 38 pt | 34–40 pt |
| 正文 | 32 pt | 28–34 pt |
| 次要说明 | 28 pt | 26–30 pt |
| 图示标注 | 26 pt | 24–30 pt |
| 表格表头 | 30 pt | 28–32 pt |
| 表格正文 | 28 pt | 26–30 pt |
| 独立公式 | 38 pt | 36–42 pt |
| 核心公式 | 42 pt | 40–46 pt |
| 页脚、来源 | 20 pt | 18–22 pt |
| 自动告警下限 | 24 pt | 仅告警，不强制写回 |

- 32 pt 是正文推荐值，不是无条件覆盖值。
- 正文封顶 36 pt：原字号大于 36 pt 时写回 36 pt 并报告；不超过 36 pt 的正文保留原字号，不因封顶而放大。AutoSize 文本框在封顶后必须恢复原始几何（位置与宽高不变），无法恢复时回滚字号并报告。
- 封顶适用于全部文本角色（含启发式判定的标题文本）；占位符标题、二级标题、章节标题页，以及字号不小于 56 pt 的展示性大字不封顶。
- 24 pt 是告警阈值，不是普通正文推荐值。
- 放大后可能新增换行、溢出或遮挡时，保留原字号并报告。
- 禁止通过扩大文本框、移动或缩小其他对象来容纳目标字号。

### 5.3 白底配色

| 用途 | 默认色值 |
|---|---|
| 页面背景 | `#FFFFFF` |
| 正文 | `#000000` |
| 辅助文字 | `#222222` |
| 重点红 | `#C00000` |
| 公式蓝 | `#004C99` |
| 实验绿 | `#006B3C` |
| 结论浅黄底 | `#FFF2CC` |
| 公式浅蓝底 | `#D9EAF7` |
| 普通边框 | `#666666` |

- 白底正文使用黑色或接近黑色，不使用浅灰正文。
- 黄色只用于填充，不用于白底正文。
- 不使用高饱和刺眼颜色作为大段文字。
- 公式蓝默认使用 `#004C99`，实验绿默认使用 `#006B3C`；在浅色公式框上优先使用深蓝。
- 重要信息不能只依靠颜色表达。
- 自动颜色修改必须准确识别对象角色；无法准确识别时只报告。
- 页面背景默认只报告候选，不自动覆盖既有背景；`SLIDE.BACKGROUND` 属于显式启用的 R2 规则。

## 6. 功能需求

### FR-01 输入发现

- 支持单个 `.pptx`、`.pptm` 或目录及可选递归。
- 排除 `~$` 临时文件、历史输出和当前输出目录。
- 输入排序和输出命名必须确定、可重复。

### FR-02 只读检查

每条发现至少包含文件、页码、对象名、RuleId、严重级别、当前值、目标值、跳过原因和是否允许自动修复。

默认检查：配置字体在当前 Windows 主机是否可用（缺失时提示字体回退风险）、16:9 画布比例、小字号、异常字重、低风险颜色偏差、文本溢出、对象越界、空白页和导出失败。字体可用性和画布比例只读检查不直接改写 PPTX；结果分别写入 `CHECK.FONT.AVAILABILITY` 与 `CHECK.SLIDE.ASPECT_RATIO`。

### FR-03 安全规范化

允许写回的属性必须由配置显式定义。每次写回记录：

```text
RuleId / File / Slide / Shape / Property / Before / After / RiskLevel / Result / Details
```

写回前确认对象支持该属性；失败时恢复原属性或放弃当前对象修改。

特殊页（自动识别的封面、结尾、资源下载和附录文字页）不做任何文本样式写回，只保留装饰效果清理；其字体族、字号、字重、颜色和几何一律保留，识别与保留情况写入报告。

字体族规范化在 AutoSize 形状上引起几何回流时，先恢复原始几何；回流不超过 max(2 pt, 短边 10%) 时保留新字体并报告，回流过大才回退兼容字体，仍失败才整体回滚并跳过。

### FR-04 不可变属性验证

规范化前后必须验证：

- 幻灯片数量和顺序不变。
- 文本内容不变。
- 对象数量、位置、宽高、旋转和层级不变。
- 动画、触发器、切换效果、速度和自动计时不变；默认不改变 `AdvanceOnClick`，显式防误触模式才允许 `true -> false`。
- 媒体、超链接和包关系不变。
- 原输入文件哈希不变。

任何非允许差异均为 Blocker。

### FR-05 PowerPoint 实际验证

- 用 Microsoft PowerPoint 打开规范化副本。
- 保存操作不得触发修复提示。
- 按模式导出 PDF；深度审查模式导出逐页 PNG。
- 自动化启动 PowerPoint 时默认使用隐藏窗口和无提示模式；人工检查只针对生成副本显式打开，不把批处理窗口暴露给课堂桌面。
- COM 异常必须重试或降级并进入报告。

### FR-06 宿主 AI 视觉审查

AI 读取原始与输出的对应页 PNG，只读检查新增换行、裁切、遮挡、字体回退、乱码、可读性下降、公式显示异常和结构变化。

建议结果模型：

```json
{
  "file": "example.pptx",
  "slide": 1,
  "status": "Passed|Review|Blocked",
  "issues": [
    {
      "type": "NewWrap|Clipping|Overlap|FontFallback|Readability|StructureChange|Other",
      "severity": "Info|Warning|Error",
      "description": "",
      "evidence": ""
    }
  ]
}
```

AI 结果只能进入门禁和报告，不能直接调用写回脚本。

### FR-07 汇总与交付

默认输出结构保持：

```text
00_检查报告/
01_交付物/   （规范化 PPTX 与同名导出 PDF 存放在同一目录）
03_原始备份/
summary.md
review-manifest.json
```

Manifest 至少包含工具/配置版本、输入输出哈希、文件状态、修改/跳过数量、不可变验证、PowerPoint/PDF/PNG 验证、AI 门禁状态及失败降级原因。

### FR-08 公式载体盘点

系统必须识别并报告至少以下公式载体：

- PowerPoint 原生 OfficeMath/OMML，包括 PowerPoint DrawingML 扩展中的 `a14:m` 和数学节点。
- MathType/OLE，包括 `Equation.DSMT4` 等可识别的 OLE 程序标识。
- 普通文本框中的公式样文本。
- 单独图片中的公式候选。
- 含题干、标注、图形或多个区域的混合图片。
- 组合对象、视频截图和无法安全分类的未知对象。

每条盘点结果必须包含文件、页码、形状标识、载体类型、原始哈希、边界框、候选状态和处理建议。盘点不得修改 PPTX。

### FR-09 受控公式识别与规范化

图片或文本公式进入写回前必须经过：

```text
候选发现 -> 公式区域裁剪 -> 识别候选 -> FormulaIR 规范化
  -> 白名单/受控语法 -> 物理符号与单位校验 -> 目标格式生成
```

要求：

- RapidOCR 只能作为文字探测或检索键，不能作为二维公式内容源。
- 专用公式模型的输出只能进入候选列表，不能直接调用 PPTX 写回。
- FormulaIR 必须保存原图/原文本哈希、识别来源、候选表达式、token 结构、公式角色、上下文、校验结果和决策原因。
- 中文角标、单位、分式、上下标、负号和隐式乘法必须有显式规则或白名单，不得依赖模型自由解释。
- 无法确定语义时，状态必须为 `ManualRequired`、`OriginalKept` 或 `FallbackSvg`。

### FR-10 OfficeMath、SVG 和 MathType 输出策略

- OfficeMath/OMML 是新建和高置信度公式的默认目标。
- SVG 只作为视觉稳定的展示型降级，不宣称可编辑。
- MathType 迁移只能走显式批次，优先取得可靠的 TeX/MathML 源；不得自行伪造或篡改 MTEF/OLE。
- 写回只允许生成新 PPTX 副本，原始 PPTX、原始图片和识别证据必须保留。
- 公式对象写回必须通过 Open XML 结构门禁、PowerPoint 实际打开/导出门禁和页面视觉门禁。

## 7. 非功能需求

### NFR-01 安全与兼容

- 默认不覆盖输入；不完整输出不得标记成功。
- 主入口默认使用 PowerShell 7（`pwsh`）；Windows PowerShell 5.1 仅作为显式兼容回退。
- `tools/*.ps1`、`examples/*.ps1` 保持 UTF-8 with BOM。
- 中文配置、CSV、Markdown 显式 UTF-8；CSV 写 UTF-8 BOM。
- 默认普通文本字体保持微软雅黑、Arial；公式拉丁/希腊字符使用 Cambria Math，中文角标使用 `fonts.mathEastAsian`（默认宋体，可按课件样本配置）。

### NFR-02 可维护

- 工作流编排、规则判定、COM 边界和报告模型职责分离。
- 新规则必须有稳定 RuleId、风险等级、测试和回归样本。
- 配置字段必须真实控制执行路径，不允许安全开关仅声明不生效。
- 不增加功能时不进行全量技术栈重写。

### NFR-03 性能与可观测

- 默认不导出逐页 PNG，不启用 OCR、AI 清晰化或联网 API。
- 性能优化必须有真实课件耗时或内存证据。
- 不默认并发启动多个 PowerPoint COM 实例。
- 每阶段记录开始、完成、失败和耗时；报告可定位具体页面和对象。

### NFR-04 公式语义安全

- 公式自动接受的首要指标是错误接受率，而不是识别召回率；模型评测必须单独报告中文角标、单位、分式方向、负号和隐式乘法错误。
- 识别模型、模型版本、权重路径、运行时、设备、输入预处理和候选排序策略必须记录到 manifest。
- 同一模型生成和自我判定不构成独立证据；视觉模型只能作为辅助复核，不能成为唯一语义门禁。
- 公式转换的阈值必须通过当前真实课件的标注样本校准，不能凭通用模型分数直接设定。
- 任何新增模型依赖必须经过许可证、权重来源、离线部署、资源占用和可删除回滚评估。

## 8. 风险模型

| 等级 | 范围 | 默认策略 |
|---|---|---|
| R0 | 读取、报告、PDF/PNG、Open XML、AI 只读审查 | 允许 |
| R1 | 字体、字号、颜色、字重、确定性的简单填充/边框 | 验证通过后交付 |
| R2 | 段落、行距、字符间距、文本框内边距、母版 | 默认关闭，独立授权 |
| R3 | 移动/缩放、扩宽文本框、动画、非授权切换属性、公式语义转换、OCR 写回、重排版 | 禁止进入默认主线 |

公式专项不降低 R3 的风险等级。`ClosedWorldUnattended` 只是 R3 实验批次中的一种受控执行模式，必须有明确的模型评测、白名单、结构门禁、宿主门禁、视觉门禁和回滚证据。

## 9. 目标架构与技术栈

```text
CMD 一键入口
  -> PowerShell 7 工作流编排（pwsh；缺失时回退 5.1）
      -> 配置与规则
      -> PowerPoint COM 边界
      -> Open XML/.NET 验证器
      -> 报告与 manifest
      -> 可选逐页 PNG
          -> 宿主 AI 只读视觉审查
```

公式实验分支：

```text
PPTX 载体盘点
```

## 10. 路线图

### P0 安全契约收敛

目标：消除文档、配置和代码冲突，只改允许的样式属性。

- 默认禁用答案文本框移动、答案动画新增/修改和文本框扩宽；默认保留单击翻页，防误触模式才允许全页关闭单击翻页。
- 检查所有 `doNot...` 配置是否真实控制执行路径。
- 每项写回增加稳定 RuleId、Before、After 和结果。
- 同步 README、使用方法、自动化边界和 VBA 默认行为。

门禁：自检通过；fixture 前后页数、文本、对象几何、动画和非授权切换属性一致；默认样本 `AdvanceOnClick` 不变，防误触样本才允许变为 `false`；真实样本生成 summary 和 manifest。

### P1 不可变差异验证

目标：机器证明规范化没有改变内容、结构和讲授行为。

- 定义 PPTX 快照模型。
- 提取页面、文本、对象几何/层级、动画、切换、关系摘要。
- 只允许指定样式属性变化，其他差异标为 Blocker。
- 结果写入 manifest 和 summary。

门禁：能检测故障注入差异；只改允许样式的 fixture 能通过；失败副本不得列入成功产物。

### P2 样式规则确定化

目标：把样式规范变成可测试、可解释、不会越权的规则。

- 为字体、字号、颜色、字重、背景、边框建立 RuleId。
- 明确检测、写回、跳过条件和风险等级。
- 字号调整前后检查换行、溢出和边界。
- 无法准确识别对象角色时只报告。
- 配置增加版本和严格校验。

门禁：每条规则至少有应修改、应跳过、失败降级三个测试场景。

### P3 宿主 AI 视觉门禁

目标：用 AI 逐页比较替代大部分人工视觉复核，但不授权 AI 写回。

- 定义页面图配对、JSON Schema、审查维度和 Passed/Review/Blocked 状态。
- AI 只阻断或提示；结论进入 manifest。
- AI 不可用时降级为规则审查，不伪造 AI 通过状态。
- 逐页图仍只在深度审查时显式导出。

门禁：已知新增换行、裁切、乱码、遮挡样本能被标记；AI 无 PPTX 写回路径。

### P4 工程整理（仅在 P0–P3 证明需要时）

- 可抽出报告/manifest、只读规则和统一 COM 边界。
- 可把纯 Open XML 快照/差异逻辑迁移到小型 .NET CLI。
- 禁止全量重写、新增桌面 UI、改变一键入口或无测试搬迁 COM 写回。

当前结论：P0–P3 已形成可重复验证闭环，未发现需要进行 P4 大规模迁移的证据；P4 保持延期，不作为交付阻塞项。

### 公式专项 F0–F9（非默认实验路线）

公式专项不改变 P0–P4 默认主线。详细任务以 [`公式识别转换实施计划.md`](公式识别转换实施计划.md) 为准，主 PRD 只保留阶段门槛：

```text
F0 契约/FormulaIR/证据 schema
  -> F1 全量载体盘点与候选裁剪
  -> F2 专用模型评测与 Adapter
  -> F3 FormulaIR 归一化、白名单和物理规则
  -> F4 MathML/LaTeX/UnicodeMath 到 OMML 对照转换
  -> F5 角色化样式和 OfficeMath 写入模块
  -> F6 SVG 降级与原图保留
  -> F7 ClosedWorldUnattended 小批量真实样本
  -> F8 MathType 显式迁移和扩大范围评审
```

阶段晋级规则：前一阶段所有独立失败模式都有证据覆盖，且未引入新的默认行为，才允许进入下一阶段。F7 之前不得宣称“无人确认自动转换”，F8 之前不得宣称“全量迁移”。

## 12. 测试与发布门禁

### 最小 fixture

- 标题/正文、混合中英文数字单位、小于 24 pt 小字。
- 接近边界且放大后会换行的文本框。
- 表格、组合对象、图片旁文字、OfficeMath。
- 已有动画/切换、白底/复杂背景、中文路径。

### 故障注入

- COM 创建失败、PowerPoint 忙或 `RPC_E_CALL_REJECTED`。
- 输出不可写、损坏 PPTX、PDF 导出失败、PNG 数量不匹配。
- 配置缺字段/类型错误、AI 超时/空结果/无效 JSON。

### 交付前

- `tools/Test-ToolkitFiles.ps1` 通过。
- 相关功能的 `tools/Assert-Toolchain.ps1 -Deep` 通过。
- 输入未修改；输出能由 PowerPoint 打开并导出 PDF。
- 文本、页面结构、对象几何、动画和非授权切换属性无差异；`AdvanceOnClick` 只允许变为 `false`。
- 输出 PPTX 改动至少用一个真实 `PPTX/` 样本生成 summary 和 manifest。
- 深度审查没有新增 Blocked。
- 公式实验输出必须额外包含公式载体盘点、FormulaIR/候选清单、模型/转换器版本、写回状态、结构门禁、宿主门禁、视觉门禁和回滚路径。
- 公式自动接受不得只凭 OCR 置信度、VLM 自评或单一渲染相似度；必须同时具备 canonical 内容信号、结构信号和视觉信号。
- README、docs、参数和 `.cmd` 入口一致。
- 新工具已纳入自检；新输出目录已更新文档和 `.gitignore`。

## 13. 当前优先级结论

当前默认主线仍不应为了公式实验切换优先级；本次只完成公式专项的设计、任务拆分和验收契约。公式转换、OCR、媒体优化、AI 清晰化仍须由显式任务按 F0–F9 小步进入，不能因为文档已更新就默认执行。

```text
P0 安全契约收敛
  -> P1 不可变差异验证
  -> P2 样式规则确定化
  -> P3 宿主 AI 视觉门禁
  -> 有证据后再决定是否做 P4 工程整理
```

默认主线的核心成功标准：批量处理后更清晰、更一致，同时没有改变任何教学内容、页面结构和讲授行为。公式专项的附加成功标准是：每个公式对象有可追溯归宿，只有通过 canonical 内容、结构、宿主和视觉门禁的对象才可进入 OfficeMath 写回。
