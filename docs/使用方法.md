# 使用方法

## 1. 环境要求

- Windows 10 / Windows 11
- Microsoft PowerPoint 桌面版
- PowerShell 7（主路径；命令为 `pwsh`）
- Windows PowerShell 5.1（仅作兼容回退）
- 建议使用 `.pptx` 文件，不建议直接处理 `.ppt` 老格式

---

## 2. 第一次使用

把工具包解压到本地目录，例如：

```powershell
D:\tools\physics-ppt-toolkit
```

打开 PowerShell 7：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
pwsh -NoLogo -NoProfile
cd D:\tools\physics-ppt-toolkit
```

---

## 3. 先生成检查报告

```powershell
.\tools\Report-PhysicsPptStyle.ps1 `
  -InputPath "D:\课件\原始PPT" `
  -OutputDir "D:\课件\检查报告" `
  -Recurse
```

输出：

```text
D:\课件\检查报告\physics-ppt-normalize-report.csv
```

建议先查看报告中的问题：

- 小字号
- 非规范字体
- 配置字体是否安装（缺失时提示字体回退风险）
- 16:9 画布比例
- 疑似公式
- 视频页背景
- 表格样式
- 过度装饰效果

---

## 4. 批量规范化

```powershell
.\tools\Normalize-PhysicsPpt.ps1 `
  -InputPath "D:\课件\原始PPT" `
  -OutputDir "D:\课件\规范化输出" `
  -Recurse
```

脚本会将规范化后的 PPTX 保存到输出目录，不覆盖原文件。

---

## 5. 单个文件处理

```powershell
.\tools\Normalize-PhysicsPpt.ps1 `
  -InputPath "D:\课件\18.2电功率.pptx" `
  -OutputDir "D:\课件\规范化输出"
```

批处理期间 PowerPoint 默认以隐藏窗口、无提示模式运行，不会反复弹出空白 PowerPoint 窗口；如需人工检查，可在流程结束后打开生成的副本。根目录 `.cmd` 入口和并行 worker 都优先使用 `pwsh`，只有未安装 PowerShell 7 时才回退到 Windows PowerShell 5.1。

默认保留课件原有的鼠标单击换片行为。如需防止演示时误触换片，显式追加
`-DisableAdvanceOnClick`；该模式只修改 `AdvanceOnClick`，不会改动动画、切换效果或自动计时。

生成副本可直接用于投影前复核：工作流不会自动切换显示器、控制投影仪或在后台启动放映。使用 `-OpenGeneratedPptx` 打开规范化副本后，在 PowerPoint 中按 `F5` 从头放映，或按 `Shift+F5` 从当前页放映；投影仪/扩展屏由 Windows 和 PowerPoint 的显示设置负责。

## 7. 使用 VBA 宏

适用于希望在 PowerPoint 内直接运行的情况。

步骤：

1. 打开 PowerPoint。
2. 打开需要处理的 PPTX。
3. 按 `Alt + F11` 打开 VBA 编辑器。
4. 选择 `File > Import File...`。
5. 导入：
   - `vba\PhysicsPptCommon.bas`（共享常量与工具模块，必须先导入）
   - `vba\PhysicsPptNormalize.bas`
6. 回到 PowerPoint。
7. 按 `Alt + F8`。
8. 运行：
   - `NormalizeCurrentPresentation`

VBA 备用宏默认也保留既有页面背景；如需统一背景，先在 `vba\PhysicsPptCommon.bas` 中将
`NORMALIZE_SLIDE_BACKGROUND` 改为 `True`，并在副本上完成视觉复核。

报告型宏：

- 导入 `vba\PhysicsPptReportOnly.bas`
- 运行 `ReportCurrentPresentationStyle`

母版样式宏（可选）：

- 导入 `vba\PhysicsPptCommon.bas`（如尚未导入）与 `vba\ApplyPhysicsPptMasterStyle.bas`
- 运行 `ApplyPhysicsMasterStyleToActivePresentation`，对当前演示文稿的幻灯片母版应用保守样式默认值；只改母版文本默认，不移动已有页面对象。母版背景默认保留，仅在把 `PhysicsPptCommon.bas` 中的 `NORMALIZE_SLIDE_BACKGROUND` 改为 `True` 后才统一为白底。

## 8. 建议检查顺序

运行自动化后，人工重点检查：

1. 公式是否显示正常。
2. 视频页是否仍能播放。
3. 动画顺序是否未受影响。
4. 复杂图示是否未被错误改动。
5. 表格是否仍然排版正常。
6. 黑底视频页文字是否清楚。
7. 普通白底页的重点框是否明显。

页面背景候选默认只进入报告，不会自动把既有页面改成白底或黑底；这是为了避免误伤有意设计的实验暗底、封面和资源页。只有明确启用配置中的 `SLIDE.BACKGROUND` 规则并完成视觉复核后，才允许写回背景。

## 9. 版次化交付目录

工作流默认输出到版次化交付目录 `reports\<课件身份>_v<N>`：输出根目录自动以原始来源身份解析为下一个原子认领的版次号，文件输入会区分 `.pptx` 与 `.pptm`，`N` 取现有版次的最大值加一；无后缀的旧交付目录视为第 1 代，因此第一次版次化交付生成 `_v2`。目录号最大的即最新交付，旧版目录保留作回滚对照，确认不用后可自行归档或删除到 `reports\_archive\`。

```powershell
.\tools\Invoke-PhysicsPptWorkflow.ps1 `
  -InputPath "D:\课件\18.2电功率.pptx" `
  -Mode SafeNormalize
```

需要自定义输出位置时，显式给 `-OutputRoot` 并指向 `reports\` 之外的目录（`reports\` 为版次化交付专用根，门禁只允许 `<课件身份>_v<N>` 目录与 `_archive`）。不带 `-OutputRoot` 时版次化交付总是启用，无需再加任何参数。

需要一条命令跑完整样式链时，在工作流上加 `-BrandRefresh` 与 `-HighlightBox`：规范化之后依次执行品牌视觉刷新与强调框统一，阶段副本（`<课件名>.brand.pptx`、`<课件名>.callout.pptx`）和最终 PDF 都落在同一交付目录的 `01_交付物\` 内，`review-manifest.json` 记录各阶段产物路径。规范化与不变量门禁仍然只约束规范化副本；品牌/强调框阶段按设计改变视觉，各自在 `00_检查报告\` 留有自己的报告。可再叠加 `-ApplyFormulaOmmlWhitelist`，公式阶段会自动以链上最后一份副本为源。

## 10. 使用宿主 AI 进行只读视觉复核

需要逐页替代大部分人工比对时，先在规范化命令中加入 `-PrepareAiVisualReview`。该参数会额外生成原始/规范化 PNG 页面配对、`ai-visual-review-request.json` 和 `16_不可变快照`，不会向课件写入 AI 结果。

```powershell
.\tools\Invoke-PhysicsPptWorkflow.ps1 `
  -InputPath "D:\课件\原始PPT" `
  -OutputRoot "D:\课件\输出" `
  -Mode NormalizeAndPdf `
  -PrepareAiVisualReview
```

AI 必须按 `manual\physics-ppt-visual-review\SKILL.md` 对每页原始/规范化图进行只读比较，再输出符合其 JSON Schema 的结果。导入时会验证每一页配对、状态聚合和证据字段；`Blocked` 会写入 `review-manifest.json` 与 `summary.md`，不得交付对应输出。
若使用 `-AiVisualReviewResult` 复用已有输出目录，工作流还会核对准备包对应的输入身份、输出路径、页面图路径与页面图哈希及不变量状态；页面图证据不一致时会拒绝复用，必须重新生成 packet 和审查结果。PowerPoint 容器重保存造成的 PPTX/PDF 字节漂移本身不会替代页面图证据判断。

```powershell
.\tools\Import-PptxAiReviewResult.ps1 `
  -ManifestPath "D:\课件\输出\review-manifest.json" `
  -ResultPath "D:\课件\输出\ai-visual-review-result.json"
```

## 11. 重要建议

不要直接在唯一原件上运行任何自动化脚本。始终保留原始课件。
