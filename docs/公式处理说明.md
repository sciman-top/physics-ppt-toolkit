## 1. 推荐公式方案

初中物理 PPT 的重要公式优先使用 Office 自带公式对象，拉丁/希腊字符使用 Cambria Math，中文角标使用 `fonts.mathEastAsian`（默认宋体）。这里的“优先”是新公式和通过受控验证的公式的目标选择，不表示把已有 MathType、图片或未知对象全部强制迁移。

正文和公式之间应保持清晰层级：

- 正文：微软雅黑，32 pt，不加粗。
- 独立公式：Cambria Math，38 pt。
- 核心公式：Cambria Math，40–42 pt。

当前配置中的公式角色字号为：行内 34 pt、独立 38 pt、核心 42 pt。写回时应由公式角色和 token 类型驱动，不得把所有公式 run 固定成同一个字号或统一斜体。

推荐目标格式：

| 公式来源/状态 | 默认处理 |
|---|---|
| 已有 OfficeMath/OMML | 保留并检查 |
| 已有 MathType/OLE | 默认保留，显式迁移时单独处理 |
| 白名单普通文本公式 | 可生成 OfficeMath 副本 |
| 白名单图片公式 | 先由专用模型识别，再取白名单 canonical 源生成 OfficeMath |
| 语义正确但 OMML 不稳定 | 使用 SVG 展示兜底 |
| 无法证明语义等价 | 保留原图并标记 `ManualRequired`/`OriginalKept` |

## 2. 为什么不把所有公式全自动转换

PPT 中的公式来源复杂：

- Office 自带公式对象
- 普通文本框
- MathType 对象
- 图片公式
- 视频截图中的公式
- 组合对象内部文本

脚本和模型都不能 100% 正确理解公式边界和物理意义。因此默认策略是：

```text
只扫描和报告疑似公式。
只对白名单精确匹配的低风险独立公式走 OMML 写入 + Open XML 结构校验；逐页视觉审查自动门禁作为显式深度复核。
图片公式的 OCR/视觉模型结果只能作为检索键和候选证据，不能作为直接写回内容源。
其它公式只进入复核报告，不自动写回。

处理模式：

| 模式 | 当前状态 | 行为 |
|---|---|---|
| `ReportOnly` | 已有 | 盘点和报告，不写回 |
| `CandidateOnly` | 已有前置能力 | 输出裁剪图、OCR/模型候选和 FormulaIR 候选，不写回 |
| `ClosedWorldUnattended` | 计划中，默认关闭 | 仅对白名单/受控公式集命中项无人逐条确认，仍必须通过全部机器门禁 |
| `ReviewRequired` | 已有降级语义 | 未命中、冲突、复杂或证据不足时保留原状并进入复核 |
| `ExplicitMigration` | 样本级已验证，默认关闭 | 用户明确指定的 MathType/OLE 或专项迁移批次；必须提供 GoldSet/canonical 源 |

“无人逐条确认”不等于“AI 直接决定内容”。任何候选冲突、中文角标歧义、单位/维度失败、目标格式不支持、PowerPoint 打开失败或视觉回归，都必须自动降级。
```

## 3. 角标处理原则

常见角标应使用下标，而不是普通字符靠近。

| 文本 | 规范写法 |
|---|---|
| W有 | W 下标 有 |
| W总 | W 下标 总 |
| W额 | W 下标 额 |
| G物 | G 下标 物 |
| G动 | G 下标 动 |
| R1 | R 下标 1 |
| R2 | R 下标 2 |
| U1 | U 下标 1 |
| U2 | U 下标 2 |
| I1 | I 下标 1 |
| I2 | I 下标 2 |
| P1 | P 下标 1 |
| P2 | P 下标 2 |

## 4. 分式处理原则

正式展示时，除法优先使用上下分式，不使用斜杠形式。

| 线性写法 | 正式显示 |
|---|---|
| P = W/t | W 在上、t 在下的分式 |
| η = W有/W总 | W有 在上、W总 在下的分式 |
| I = U/R | U 在上、R 在下的分式 |
| R = U/I | U 在上、I 在下的分式 |

### 4.1 canonical UnicodeMath 书写规范（parser 强制，2026-09-14 起）

白名单 `targetUnicodeMath` 与 GoldSet `SourceFormulaText` 的 canonical 值必须遵守以下规则；违反项会被 `Export-FormulaOmmlCandidates.ps1` 确定性拒绝，不会静默产出错误结构：

| 规则 | 合法写法 | 非法写法（拒绝） |
|---|---|---|
| 上下标用 ASCII `^`/`_` 标记 | `10^(3)`、`Q_吸` | 裸 `10^-3`（运算符开头的 script 必须括号） |
| Unicode 上下标字符（³、₁ 等）仅允许出现在识别输入 | parser 自动归一化为 `^(3)`、`_(12)` | 白名单 canonical 中直接写 `10³`（会被归一，不建议） |
| `/` 分母 = 隐式乘法连贯串 | `c=Q/mΔt`（mΔt 属于分母）、`J/(kg·℃)` | — |
| 显式乘法运算符（`×`、`·`、`∙`、`*`）结束分母 | `J/(kg·℃)×50kg×20℃` | 期望分母含 `×` 时必须写括号 |
| 链式除法必须括号消歧 | `(a/b)/c` 或 `a/(b/c)` | 裸 `a/b/c` |
| `\/` 线性除号转义 | `J\/(kg·℃)`（保持线性斜杠，不产生上下分式） | 把单位斜杠写成裸 `/`（会转成上下分式） |
| 上标脚本括号是分组语法 | `10^(-3)` 渲染为抬起的 -3（无括号字符） | 期望 OMML 中出现字面括号 |

## 5. 自动化脚本的公式能力

本工具包默认只生成疑似公式报告，不默认转换公式。

疑似公式识别包括：

- 包含 `=` 的短文本框
- 包含 `/` 的公式样文本
- 包含 `η`、`Ω` 等符号
- 包含 `W有`、`W总`、`G物`、`R1`、`U1`、`I1` 等常见角标写法

报告用于人工复核和后续低风险手动处理。

自动化报告会补充公式候选分类：

- `FormulaCandidate`：疑似公式原文。
- `FormulaCandidateClass`：风险等级、公式类型、长度和跳过原因。
- `FormulaTextStyleNormalized`：低风险独立文本公式已做字体、字号、颜色和居中归一。
- `FormulaStyleSkipped`：公式样式处理被跳过，通常是长句、复杂文本或配置关闭。
- `FormulaWhitelistCandidate`：命中固定物理公式白名单，后续可走 OMML 自动门禁。
- `FormulaConversionSkipped`：命中白名单，但 `formulaConversionDefault=false`，因此不做语义转换。

当前低风险样式归一只处理普通文本框中的短独立公式，不改写公式内容，不把公式转换为 OfficeMath。
如需关闭该能力，可在 `config/physics-ppt-style.config.json` 中设置：

```json
"formulaTextStyleDefault": false
```

完整实施路线见 `docs/公式排版优化路线图.md`。

白名单公式配置位于 `formulaWhitelist`。每条规则包含：

- `name`：公式名称。
- `sourcePattern`：匹配去空白后的原始文本。
- `targetUnicodeMath`：建议转换目标。
- `targetTex`：SVG 渲染目标。
- `note`：复核或自动门禁提示。

后续公式迁移计划允许在不破坏现有字段的前提下增加：

- `canonicalFormulaIR`：经审定的 token/结构化公式源；它是自动写回的内容真值。
- `canonicalMathML`：用于结构复核和 MathML-to-OMML 转换的 Presentation MathML。
- `sourceKinds`：允许匹配的来源，如 `Text`、`Image` 或显式 `MathTypeExport`。
- `allowedContexts`：公式附近的物理量名称、题型或教材语境约束。
- `formulaRole`：`inline`、`standalone` 或 `core`。
- `unitPolicy`：单位、量纲和温差定义约束。
- `status`、`reviewVersion`、`reviewedAt`：白名单版本和审定状态。

这些字段在实现前必须先进入 schema 和测试；不能仅修改文档后就把未知字段当成已支持配置。白名单本身也必须接受校验，不能把“命中白名单”解释为绝对正确。

工作流会额外生成 `10_复核索引/formula-review.csv`，按单条公式汇总原文、分类、白名单命中、转换状态、样式状态和建议动作。

一键流程会生成 `10_复核索引/formula-whitelist-suggestions/formula-whitelist-suggestions.csv`。该清单只用于扩大白名单前的证据整理：它会按出现频率、文件覆盖数、表达式完整性和已配置白名单覆盖情况，把候选分为 `PromoteCandidate`、`ReviewCandidate`、`ReviewSubscriptOnly`、`ExistingWhitelist` 或 `Rejected`。它不会自动修改 `config/physics-ppt-style.config.json`，也不会自动写回 PPTX。

单独生成白名单建议清单时，可使用：

```powershell
powershell -File tools\Export-FormulaWhitelistSuggestions.ps1 `
  -FormulaReviewCsv "reports\pptx_dir_enhanced_visual_v3\10_复核索引\formula-review.csv" `
  -OutputDir "reports\formula_whitelist_suggestions" `
  -MaxSuggestions 120
```

白名单晋升规则：只有来源表达式稳定、canonical FormulaIR/`targetUnicodeMath`/`targetTex` 可复核、必要的上下文和单位定义明确、OMML 片段可解析、PPTX 副本 Open XML 校验通过，才应把建议项写入配置；批量扩大白名单前建议再抽样运行 `-FormulaOmmlVisualAudit` 做渲染复核。初中课件默认保留教材常见写法：`W总=Fs` 可以转换为可编辑下标 `W_总=Fs`，但不自动改成 `W_总=F·s`。`Q吸`、`Q放` 等热学公式必须依据实际教材定义确认温差方向后再加入，不能仅凭模型建议写入。

复杂公式可先渲染为 SVG 做展示型验证：

```powershell
npm install
node tools/Render-FormulaSvg.mjs --tex "P=\frac{W}{t}" --out reports\formula_svg_smoke\power.svg
```

SVG 路线只保证展示清晰，不等同于 PowerPoint 内可编辑公式。可编辑终态应优先使用 OfficeMath/OMML。

对白名单公式先生成可编辑候选片段时，使用：

```powershell
powershell -File tools\Export-FormulaOmmlCandidates.ps1 `
  -FormulaReviewCsv "reports\formula_route_workflow_check\10_复核索引\formula-review.csv" `
  -OutputDir "reports\formula_omml_candidates"
```

该脚本会输出：

- `formula-omml-candidates.csv`：白名单公式、页码、形状、目标表达式和片段路径。
- `fragments/*.mathml.xml`：可供 Microsoft 365 MathML 导入链路复核的 Presentation MathML。
- `fragments/*.omml.xml`：后续 PPTX 写入器可使用的 `a14:m/m:oMath` 候选片段。

该脚本不修改 PPTX，也不隐藏或删除任何形状。

对白名单候选做可编辑 OfficeMath 副本试验时，使用：

```powershell
powershell -File tools\Apply-FormulaOmmlWhitelist.ps1 `
  -InputPath "PPTX\12.4机械效率（王耀强）.pptx" `
  -FormulaReviewCsv "reports\formula_route_workflow_check\10_复核索引\formula-review.csv" `
  -OmmlCandidateCsv "reports\formula_omml_candidates\formula-omml-candidates.csv" `
  -OutputPath "reports\formula_omml_apply_smoke\12.4机械效率（王耀强）.formula-omml.pptx"
```

该脚本只保存新 PPTX；只替换“整段文本精确等于白名单公式”的段落，避免误删同一文本框中的说明文字。插入失败时保持该段不变并写入 `formula-omml-apply-report.csv`。

写入后建议用 Open XML 验证器复核包结构和 OfficeMath 数量：

```powershell
& "$env:USERPROFILE\.dotnet\dotnet.exe" run `
  --project tools\FormulaOfficeMathValidator\FormulaOfficeMathValidator.csproj `
  -c Release -- `
  "reports\formula_omml_apply_smoke\12.4机械效率（王耀强）.formula-omml.pptx" `
  --max-errors 10
```

验证通过不代表视觉最终通过，还必须用 PowerPoint 导出 PDF 和页面 PNG 进入视觉审查门禁；人工目检只用于抽样或异常定位。

本地规则视觉审查可使用：

```powershell
powershell -File tools\Export-PptxVisualAudit.ps1 `

```

该脚本输出：

- `pages/slide-xxx.png`：每页渲染图。
- `*.pdf`：固定版式 PDF。
- `pptx-visual-audit.csv`：空白页、贴边、越界、疑似溢出、小字号、公式文本等审查项。
- `pptx-shape-audit.csv`：形状位置、字号、字体、公式文本候选。
- `pptx-visual-audit.contact-sheet.png`：全页联系表，便于直接看图复核。

自动确认门禁可继续读取上述视觉审查产物：

```powershell
powershell -File tools\Export-PptxVisualConfirmation.ps1 `
  -VisualAuditDir "reports\formula_omml_visual_audit" `
  -ContactSheet
```

该脚本输出：

- `pptx-visual-confirmation.csv`：按页给出 `Passed`、`PassedWithKnownIssues`、`NeedsReview` 或 `Failed`。
- `pptx-visual-confirmation-manifest.json`：汇总 `automationGateStatus`、新增错误、需复核页和失败页。

对视觉审查中明确的形状越界做低风险副本修复时，使用：

```powershell
powershell -File tools\Apply-PptxVisualAuditFixes.ps1 `
  -InputPath "reports\formula_omml_apply_smoke\12.4机械效率（王耀强）.formula-omml.pptx" `

```

该脚本目前只处理 `ShapeOutOfSlideBounds`，并且只对仍与画布相交、无需缩放即可回到安全区域的形状做平移修复。完全在画布外的对象、需要缩放才放得下的对象、可能是有意裁切的大图，都会写入跳过原因并保留原状。它不会删除空白页，不会改公式文本，也不会覆盖原 PPTX。

## 6. 图片公式的处理边界

图片公式可以转换成可编辑 OfficeMath，但不能直接跳过识别、归一化和视觉门禁。目标是“所有图片公式都有明确归宿”，而不是“所有图片公式都强制变成公式对象”。推荐链路是：

```text
图片候选定位 -> 公式区域裁剪 -> OCR 得到 LaTeX/MathML -> 归一化到白名单/受控公式源 -> 生成 MathML/OMML 候选 -> 写入 PPTX 副本 -> Open XML + PDF/页面图视觉门禁
```

当前工具包对图片公式只默认做到候选和片段阶段；专用模型和无人逐条确认属于后续显式实验：

- 图片公式默认不自动 OCR、不自动替换。
- RapidOCR 只做通用文字探测和检索键，不能承担分式、上下标、根式等二维结构识别。
- PP-FormulaNet、UniMERNet、pix2tex 等专用模型的输出只能作为 top-k 候选，必须经过 FormulaIR 规范化；不能把模型输出直接作为写回内容。
- OCR 结果必须先以 LaTeX/MathML/UnicodeMath 候选进入报告；只有归一化到白名单或受控公式源后，才能进入自动写回门禁。
- 白名单 canonical FormulaIR/TeX 才是写回内容源；识别结果只用于候选匹配、上下文判断和证据记录。
- 无法稳定识别的图片公式保留原图，必要时只做 SVG/PNG 展示兜底。
- 任何可编辑公式写入都必须保存为新 PPTX，并保留原对象作为回滚点。

从已有图片候选清单筛出疑似公式/变量标注图片时，使用：

```powershell
powershell -File tools\Export-FormulaImageCandidates.ps1 `
  -ImageCandidateCsv "reports\final_image_candidates\pptx-image-candidates.csv" `
  -OutputDir "reports\formula_image_candidates" `
  -ExportCandidates `
  -ContactSheet
```

该脚本输出：

- `formula-image-candidates.csv`：候选图片、页码、视觉特征、候选等级和建议动作。
- `formula-image-candidates.contact-sheet.png`：候选联系表，便于快速目检。
- `formula-image-candidates/`：从 PPTX 副本中导出的候选原图。

对候选图做免费本地 OCR 探测时，使用：

```powershell
powershell -File tools\Invoke-FormulaImageOcrProbe.ps1 `
  -FormulaImageCandidateCsv "reports\formula_image_candidates\formula-image-candidates.csv" `
  -OutputDir "reports\formula_image_ocr" `
  -MaxImages 20 `
  -MaxPixels 1500000
```

该脚本使用本地 Python + RapidOCR，只生成复核报告：

- `formula-image-ocr.csv`：OCR 文本、置信度、公式信号、建议动作。
- `formula-image-ocr.contact-sheet.png`：候选图与 OCR 文本联系表。
- `SuggestedAction=ReviewOcrFormulaText`：优先归一化到白名单或受控公式源，再决定是否可转为 MathML/OMML。
- `SuggestedAction=ReviewOcrPhysicsLabels`：多为物理图示变量标注，不能直接当作公式。
- `SuggestedAction=ManualVisualReview`：OCR 不足以判断，保留人工目检。

RapidOCR 当前只是文字 OCR 探测，不是专用数学公式识别模型。若后续需要把图片公式自动转 LaTeX，优先评估 `PP-FormulaNet_plus-M/L`，以 UniMERNet 和 pix2tex/LaTeX-OCR 作对照；必须把模型权重、运行时、CPU/GPU 成本、许可证、中文角标/单位错误率和错误接受率纳入任务清单。PaddleOCR 当前文档已提供 PP-FormulaNet/UniMERNet 的公式识别流水线，但其官方 benchmark 不能替代本仓真实课件 benchmark。

### 6.1 无人逐条确认的适用范围

无人逐条确认只适用于封闭世界：图片候选必须唯一命中已审定的白名单或受控公式语法，且通过以下独立信号：

1. 原图/裁剪图/页面/形状哈希和边界框绑定正确。
2. 识别候选与白名单条目及上下文相容。
3. canonical FormulaIR 的变量、中文角标、单位、分式、上下标和负号校验通过。
4. 生成的 OMML 或 SVG 可以回显，结构可解析。
5. PowerPoint 打开、保存和导出不触发修复。
6. 公式区域没有新增裁切、溢出、遮挡、基线错位或明显视觉回归。

任意一项失败都必须输出 `ManualRequired`、`OriginalKept` 或 `FallbackSvg`，不能输出 `Converted`。VLM 可以帮助发现视觉异常，但不能单独证明物理语义正确，也不能由同一模型生成后自我验收。

### 6.2 图片公式模型选择原则

模型选择不采用“某模型绝对最好”的静态结论，而采用本仓 gold set 的错误接受率优先规则：

| 候选 | 计划角色 | 主要风险 |
|---|---|---|
| RapidOCR | 通用文字探测/检索键 | 不理解二维公式结构 |
| PP-FormulaNet_plus-M | 中文课件首选评测候选 | 需要 Paddle/PaddleX 运行时；官方成绩需本仓复核 |
| PP-FormulaNet_plus-L | 复杂公式高质量候选 | 资源和延迟更高 |
| UniMERNet | 截图、复杂、真实场景对照 | 模型较大，中文和本仓样本效果需实测 |
| pix2tex/LaTeX-OCR | 拉丁数学公式基线 | 中文角标、单位和教材混合图需专项验证 |
| SimpleTex/Mathpix 等联网 API | 可选二审或对照 | 认证、隐私、网络、费用和服务变化；默认关闭 |

### 6.3 处理状态

每个公式对象必须归入以下状态之一：

| 状态 | 含义 |
|---|---|
| `NativeKept` | 已经是 OfficeMath，未迁移 |
| `Converted` | 从文本或图片生成 OfficeMath，所有门禁通过 |
| `FallbackSvg` | canonical 内容已确认，但采用 SVG 展示 |
| `OriginalKept` | 未修改，保留原始图片或 MathType |
| `ManualRequired` | 需要补充 canonical 源或人工判断 |
| `Skipped` | 非公式、混合图、组合对象或策略明确跳过 |
| `Failed` | 尝试处理失败，已回滚并保留原状 |

## 7. Pandoc 与 OMML 转换器的职责

Pandoc 可以把输入文档中的数学表达式输出为 OMML，适合作为新文档生成、转换结果对照和测试夹具工具；它不负责从图片恢复公式语义，也不应整体重写需要保留页面结构的既有 PPTX。现有 PPTX 原位或定点写回仍以 Open XML 写入器为主，PowerPoint COM 负责真实宿主打开、保存和导出验证。

`mathml2omml`、`node-latex-to-omml` 等开源库可以作为可替换转换 Adapter，但正式纳入前必须固定版本、锁定依赖、检查许可证、验证 PowerPoint `a14:m` 封装，并用本仓公式样本测试分式、根式、中文角标、单位和多行公式。不要把第三方库的 README 示例直接当成 PPTX 生产门禁。

MathType/OLE 不采用自研 MTEF 写入路线。若用户明确要求迁移，应优先从 MathType/Office 获得可靠的 TeX/MathML 或人工审定的 FormulaIR；当前样本级实现使用视觉证据绑定的 GoldSet/canonical UnicodeMath，生成独立副本并保留 `mc:Fallback` 原 OLE；没有可靠源时仍保留 MathType 对象。

2026-09-11 的 `14.1燃料的热值、效率（王耀强）.pptx` 试点已将 8 个 `Equation.DSMT4` OLE 转成 8 个 OfficeMath choice（原 OLE fallback 保留），并通过 Open XML、PowerPoint 29 页导出和第 6/9/16 页视觉对照。该结果是显式迁移试点，不代表图片公式或全部 MathType 可无人确认迁移。

## 8. 增强一键：白名单公式转可编辑 OMML

默认一键处理仍以安全排版、PDF、复核清单、白名单建议、OMML 副本和 Open XML 结构校验为主，不静默改变公式语义。全量逐页 PNG 视觉审查、视觉修复副本和 OMML 视觉审查属于重型复核环节，默认不启用。需要把白名单命中的独立公式转换成 PowerPoint 可编辑公式时，使用中速增强开关：

```powershell
powershell -File tools\Invoke-PhysicsPptWorkflow.ps1 `
  -InputPath "PPTX" `
  -Recurse `
  -Mode NormalizeAndPdf `
  -SkipPreflightReport `
  -ApplyFormulaOmmlWhitelist `
  -OpenGeneratedPptx
```

也可以直接运行仓库根目录的 `一键规范化导出并转换可编辑公式.cmd`。

增强链路会新增：

- `14_公式OMML副本/`：基于规范化/视觉修复后的 PPTX 生成可编辑 OfficeMath/OMML 副本。
- `14_公式OMML副本/_candidates/`：从 `formula-review.csv` 导出的 MathML/OMML 片段和候选清单。
- `15_公式OMML审查/`：默认包含 Open XML 校验报告；只有显式传入 `-FormulaOmmlVisualAudit` 时才生成 PowerPoint 导出的 PDF/PNG、视觉审查 CSV 和联系表。
- `10_复核索引/formula-whitelist-suggestions/`：公式白名单建议清单，只用于后续人工晋升和自动门禁复测，不自动改配置。

该链路只处理 `formula-review.csv` 中 `SuggestedAction=ReviewWhitelistConversion` 的白名单公式；原始 PPTX、普通规范化 PPTX 和视觉修复副本都不会被覆盖。`review-manifest.json` 中会记录每个 OMML 副本的 `automationGateStatus` 和 `automationGateReason`。

需要深度视觉闭环时，再显式追加：

```powershell
-IncludeReviewArtifacts -IncludeVisualAudit -ApplyVisualAuditFixes -FormulaOmmlVisualAudit
```
