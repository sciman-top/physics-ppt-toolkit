## 1. 决策摘要

### 1.1 目标终态

本专项的目标不是强制把每个公式对象都转换成 OfficeMath，而是让每个公式对象都有可追溯、可回滚、经过验证的处理归宿：

```text
NativeKept       已经是 OfficeMath，保留
Converted        通过内容、结构、宿主和视觉门禁，转换为 OfficeMath
FallbackSvg      canonical 内容已确认，但采用 SVG 展示
OriginalKept     保留原始图片或 MathType/OLE
ManualRequired   缺少可靠 canonical 源或存在语义歧义
Skipped          非公式、混合图、组合对象或策略明确跳过
Failed           尝试处理失败，已回滚并保留原状
```

只有 `Converted` 才表示写入了 PowerPoint 原生 OfficeMath。`FallbackSvg` 只表示视觉展示兜底，不表示可编辑；`OriginalKept` 不是失败，而是安全的保真结果。

### 1.2 核心决策

1. OfficeMath/OMML 是新公式和高置信度受控公式的默认目标。
2. 已有 OfficeMath 不重复转换。
3. MathType/OLE 默认保留；迁移必须是显式批次，不能自行生成或篡改 MTEF。
4. 图片公式可以识别，但模型输出只能作为检索键和候选证据，不能直接作为写回内容。
5. 白名单维护的 canonical FormulaIR/TeX/MathML 是自动写回的内容真值。
6. `ClosedWorldUnattended` 允许取消逐条人工点击，但不取消 FormulaIR、结构、宿主和视觉门禁。
7. Pandoc、MathJax、`mathml2omml` 等只承担转换或对照职责，不承担既有 PPTX 的结构保留型整体重写。
8. 发生不确定、候选冲突、门禁失败或依赖不可用时，自动降级并保留原对象。

## 2. 范围和非目标

### 2.1 本专项要解决的问题

- 识别 PPTX 中所有公式载体，而不是只扫描普通文本；
- 把图片公式和 MathType 等异构输入统一为可验证的中间表示；
- 将可证明等价的公式生成 OfficeMath/OMML；
- 对复杂或不兼容公式提供 SVG 或原图兜底；
- 取消封闭白名单公式的逐条人工点击，同时保留机器证据；
- 使识别器、转换器和写入器可以替换，而不改变安全边界；
- 让 AI 编码代理能够以单任务、小写入集合、可回滚的方式推进。

### 2.2 明确不做

- 不把 VLM/OCR 输出直接写入 PPTX；
- 不承诺任意图片、低清图片或手写公式 100% 正确恢复；
- 不重新实现 MathType 的 MTEF/OLE 二进制生成；
- 不通过 Pandoc 整体重写既有 PPTX；
- 不改变题干、答案、物理结论、页面顺序、对象层级、动画或讲授行为；
- 不默认联网、下载大模型、安装 Paddle/PyTorch 或启动多个 PowerPoint；
- 不在没有真实样本证据时打开图片公式自动写回；
- 不把 SVG 伪称为 OfficeMath 可编辑公式；
- 不把一次 VLM 视觉判断、BLEU/CDM 分数或 OCR 置信度当作语义正确证明。

## 3. 术语、模式和状态

### 3.1 公式载体

| 载体 | 识别方式 | 默认动作 |
|---|---|---|
| `OfficeMath` | Open XML 的 `a14:m`、OMML 数学节点或 PowerPoint 原生对象 | `NativeKept` |
| `MathTypeOle` | `p:oleObj`、`Equation.DSMT4` 等 OLE 标识 | `OriginalKept` |
| `TextFormula` | 普通文本框中的短公式样文本 | 白名单/受控语法候选 |
| `FormulaImage` | 单独图片中的公式区域 | `CandidateOnly` |
| `MixedImage` | 题干、标注、图形和公式混合的图片 | 分割成功后继续，否则保留 |
| `GroupFormula` | 组合对象内部文本或图片 | 默认跳过并报告 |
| `Unknown` | 无法可靠判断的对象 | `ManualRequired` 或 `Skipped` |

### 3.2 处理模式

| 模式 | 是否写回 | 适用范围 |
|---|---:|---|
| `ReportOnly` | 否 | 载体盘点、候选统计和风险报告 |
| `CandidateOnly` | 否 | OCR/模型识别、FormulaIR 候选和 SVG/OMML 片段 |
| `ReviewRequired` | 否 | 未命中、冲突、低置信度和复杂公式 |
| `ClosedWorldUnattended` | 是 | 只处理版本化白名单和受控公式集 |
| `ExplicitMigration` | 是 | 用户明确指定的 MathType/OLE 或专项迁移批次 |

所有模式都必须生成报告。只有 `ClosedWorldUnattended` 和 `ExplicitMigration` 可以写回，而且必须写入新的 PPTX 副本。

### 3.3 “无人确认”的精确定义

无人确认仅表示批处理中不要求人逐条点击“确认”。它不表示：

- AI 可以自由决定公式内容；
- 识别器可以直接覆盖原图；
- VLM 可以作为唯一裁判；
- 失败项可以静默跳过；
- 白名单无需版本、来源和测试。

`ClosedWorldUnattended` 的自动接受条件是：唯一候选命中白名单或受控公式语法，canonical FormulaIR 通过规则，目标格式可生成，结构门禁通过，PowerPoint 能打开并导出，视觉门禁无新增错误。任一条件不满足即降级。

## 4. 目标架构

### 4.1 外部 seam

以 `FormulaPipeline` 作为唯一外部 seam。调用方不应直接调用识别器、MathML 转换器或 PPTX XML 写入函数。

建议的最小 Interface：

```text
Analyze(inputPptx, options) -> FormulaManifest
Plan(formulaManifest, policy) -> ConversionPlan
Apply(conversionPlan, outputCopy) -> WriteReceipt
Verify(writeReceipt, gates) -> AcceptanceReceipt
```

Interface 需要约定输入、输出、顺序、失败状态、路径相对化、哈希绑定和不可变属性；不应把具体模型名、XML 节点细节或 PowerPoint COM 对象暴露给调用方。

### 4.2 内部 Implementation

```text
FormulaPipeline
  |
  +-- CarrierClassifier
  |     OfficeMath / MathTypeOle / TextFormula / FormulaImage / MixedImage
  |
  +-- CandidateExtractor
  |     文本提取、媒体导出、公式区域裁剪、上下文和边界框
  |
  +-- RecognitionAdapter
  |     RapidOCR / PP-FormulaNet / UniMERNet / pix2tex / 可选联网 API
  |
  +-- FormulaNormalizer
  |     候选 -> FormulaIR -> canonical TeX/MathML/UnicodeMath
  |
  +-- PhysicsPolicyValidator
  |     白名单、受控语法、中文角标、单位、维度、上下文和角色
  |
  +-- TargetAdapter
  |     OfficeMathAdapter / SvgAdapter / OriginalKept
  |
  +-- PptxCopyWriter
  |     只写副本、保持几何和层级、保存回滚证据
  |
  +-- StructuralGate
  +-- PowerPointHostGate
  +-- VisualGate
  +-- EvidenceWriter
```

这是一个 deep module：复杂识别、规范化、转换和验证逻辑隐藏在小 Interface 后面。`RecognitionAdapter` 和 `TargetAdapter` 是真实变化点；如果只有一个实现，不应为了形式创建多层空壳。

### 4.3 当前代码的渐进式归宿

第一阶段不要一次性创建大量新模块。优先在已有脚本上增加可测试的纯函数和 JSON 边界：

- 载体盘点：扩展现有报告/扫描逻辑；
- 图片候选：复用 `Export-FormulaImageCandidates.ps1`；
- RapidOCR：保持 `Invoke-FormulaImageOcrProbe.ps1` 的只读契约；
- OMML：先修复并复用 `Export-FormulaOmmlCandidates.ps1` 与 `Apply-FormulaOmmlWhitelist.ps1`；
- 只有当第二个识别器或第二个目标 Adapter 实际接入后，才抽出 `tools/Formula/` 内部目录。

## 5. FormulaIR 数据契约

### 5.1 设计原则

- 原始对象永远可追溯；
- OCR/模型候选与 canonical 内容分离；
- TeX、MathML、UnicodeMath 和 OMML 是表示，不是唯一真值；
- token 结构比原始字符串更重要；
- 所有路径相对于本次输出根目录；
- 所有外部模型输出都要带版本、权重哈希和运行时信息；
- schema 变化必须版本化，旧报告应能被安全读取或明确拒绝。

### 5.3 Token 类型

至少支持以下 token 类型；不支持的 token 必须显式标记，而不是丢失：

```text
Identifier       变量、希腊字母
Number           数字、小数、科学计数法
Operator         + - = < > ≤ ≥ × · /
Unit             kg、J、m/s、℃ 等
Text             中文标签或受控文本
Subscript        下标
Superscript      上标
Fraction         分式
Root             根式
Delimiter        括号、绝对值和界限
Accent           Δ、箭头、向量或受支持重音
Unsupported      未知或未映射结构
```

## 6. 载体处理策略

### 6.1 OfficeMath

- 通过 Open XML 统计和 PowerPoint/COM 交叉确认；
- 默认 `NativeKept`；
- 不因字体统一而重建已有公式；
- 若结构损坏，只报告，不在普通样式批次中修复；
- 需要修复时单独创建 OfficeMath 修复批次和回滚点。

### 6.2 MathType/OLE

优先级：

1. 保留原 OLE；
2. 如果 MathType/Office 能提供可靠的 TeX、MathML 或其他结构化导出，则进入 FormulaIR；
3. 对导出的 canonical 源做独立验证后生成 OfficeMath 副本；
4. 无可靠源或目标视觉不稳定时继续保留 OLE。

禁止：

- 直接解析后重建未经验证的 MTEF；
- 猜测 `Equation.DSMT4` 内部内容；
- 因为目标环境没有 MathType 就静默删掉 OLE；
- 把 MathType 复制后变成的图片当成可编辑 MathType。

### 6.3 普通文本公式

只有以下条件同时成立，才允许进入 OfficeMath：

- 文本框或段落边界明确；
- 公式不是长句的一部分；
- 命中白名单或受控语法；
- 中文角标、单位、分式、上标和下标有确定解释；
- canonical FormulaIR 已确认；
- 目标 OMML 片段与项目样式通过验证。

### 6.4 图片公式

图片处理必须保存三份关联：

```text
原始 PPTX 媒体 -> 图片原图 -> 公式裁剪图 -> recognition/canonical/evidence
```

图片候选不能只保存 OCR 字符串。必须保存原图哈希、裁剪边界、页面/形状引用、上下文、模型候选、canonical 源和最终状态。

### 6.5 混合图片和组合对象

如果图片同时含有题干、图形、标注和公式：

- 优先使用布局/公式区域检测得到独立公式裁剪；
- 裁剪不稳定时保持整张图片；
- 不把整张混合图片送入公式识别器后直接替换；
- 组合对象默认整体保留，除非建立单独的拆组和几何回滚方案。

## 7. 识别模型评测计划

### 7.1 候选模型

| 模型/工具 | 计划角色 | 选择依据 | 不得直接推出的结论 |
|---|---|---|---|
| RapidOCR | 文字探测、上下文和检索键 | 当前已接入、离线、低成本 | 不能证明二维公式结构 |
| `PP-FormulaNet_plus-M` | 中文课件首选评测候选 | 官方文档增加中文公式支持 | 不能直接证明本仓最优 |
| `PP-FormulaNet_plus-L` | 复杂公式高质量候选 | 更大模型和复杂公式场景 | 不能忽略资源/延迟成本 |
| UniMERNet | 截图、复杂、真实场景对照 | 训练和评测覆盖真实场景 | 不能只凭项目宣传选型 |
| pix2tex/LaTeX-OCR | 拉丁数学公式基线 | 开源、图片到 LaTeX | 不能假定中文角标可靠 |
| SimpleTex/Mathpix | 可选外部对照或二审 | 可能提供结构化公式输出 | 默认关闭，不能当免费或永久可用依赖 |

### 7.2 gold set

gold set 必须来自当前真实课件或同分布样本，并保存人工审定的 canonical FormulaIR。至少覆盖：

- 清晰屏幕截图；
- 压缩、缩放和低分辨率图片；
- 中文角标：吸、放、总、有、额、物、动；
- 希腊字母和特殊符号；
- 分式、根式、上下标和科学计数法；
- 单位：kg、J、m/s、℃、J/(kg·℃)；
- 负号、短横线和减号混淆；
- 公式与题干、图形、箭头混合；
- 公式区域过窄、透明边距和有意裁切。

gold set 本身是内容证据，不应混入普通 `reports/` 产物，也不应未经授权提交大体积模型或图片资产。

### 7.3 评测指标

必须优先关注错误接受，而不是只关注召回率：

```text
FormulaIR exact match
Canonical token exact match
Chinese subscript accuracy
Unit accuracy
Fraction numerator/denominator accuracy
Sign and exponent accuracy
Whitelist retrieval precision
Whitelist retrieval recall
False-accept rate
Original-kept rate
SVG fallback rate
CPU/GPU latency
Peak memory
Model size and startup time
```

发布 `ClosedWorldUnattended` 前，gold set 中不得存在未解释的高风险错误接受。阈值必须来自本仓样本校准，并写入模型评测报告和 manifest；不能把模型返回的通用 score 直接当作发布阈值。

### 7.4 模型 Adapter 协议

输入：


## 8. FormulaIR 规范化和物理规则

### 8.1 规范化顺序

```text
原始候选
  -> Unicode/空白/全半角归一
  -> LaTeX/MathML 语法解析
  -> token 树构建
  -> 变量/单位/中文文本角色识别
  -> 白名单或受控语法匹配
  -> canonical FormulaIR
  -> canonical TeX/MathML/UnicodeMath
```

不能用连续字符串替换代替完整的 token/结构解析。字符串替换只适合白名单入口的表面归一，例如空格、全角等号和教材允许的乘法符号别名。

### 8.2 中文角标

以下写法只有在白名单或上下文规则明确时才转换为下标：

```text
W总 -> W_总
W有 -> W_有
W额 -> W_额
G物 -> G_物
Q吸 -> Q_吸
Q放 -> Q_放
```

不得把任意相邻中文都当成下标。`Q吸=cmΔt` 与 `Q放=cmΔt` 的 canonical 形式还必须记录温差定义；不能只凭表面字符串添加白名单。

### 8.3 单位和隐式乘法

- 单位默认直立，不作为变量斜体化；
- `kg·℃`、`J/(kg·℃)` 的点号、括号和除法关系必须保存；
- 初中教材中 `W=Fs` 的隐式乘法不能被无证据改成 `W=F·s`；
- 识别出单位但无法判断其是否属于公式时，进入 `ManualRequired`；
- 量纲检查可以发现部分错误，但不能证明公式语义全部正确。

### 8.4 物理规则边界

规则校验可以检查：

- 变量是否在允许的公式中出现；
- 单位和量纲是否相容；
- 分式和上下标是否完整；
- 负号、指数和括号是否成对；
- 公式是否符合当前白名单的上下文。

规则校验不能独立决定：

- 教材中 `Δt` 的方向定义；
- 两个量纲都成立的不同公式哪个符合题意；
- 图片中模糊符号的真实含义；
- 公式在图形标注中是否代表矢量、变量还是普通标签。

## 9. 目标格式和转换 Adapter

### 9.1 表示层职责

```text
FormulaIR
  +-- canonical TeX
  +-- Presentation MathML
  +-- UnicodeMath
  +-- PowerPoint OfficeMath/OMML
  +-- SVG fallback
```

FormulaIR 是内部真值。目标 Adapter 只能消费 FormulaIR，不得直接消费未经归一化的 OCR 字符串。

### 9.2 转换器选型

| Adapter | 职责 | 当前定位 |
|---|---|---|
| `DirectControlledWriter` | 简单白名单公式 | 现有 PowerShell 原型，优先修正样式和结构 |
| `MathMLToOmmlAdapter` | Presentation MathML 到 OMML | 可评估 `mathml2omml`，需 PowerPoint 自测 |
| `LatexToOmmlAdapter` | LaTeX 经 MathML 到 OMML | 可评估 `node-latex-to-omml`，不直接写 PPTX |
| `PandocReferenceAdapter` | 生成 docx/pptx 夹具并对照 OMML | 参考链，不作为既有 PPTX 写回器 |
| `SvgAdapter` | canonical 源到 SVG | 展示兜底，不标记可编辑 |
| `MathTypeAdapter` | 只消费可靠 MathType 导出源 | 计划中，不生成 MTEF |

第三方库正式纳入前必须完成：版本锁定、许可证检查、依赖清单、最小样例、复杂公式样例、中文角标样例、PowerPoint 打开和回滚测试。

### 9.3 OMML 写入边界

`OfficeMathAdapter` 必须：

- 输出符合 PowerPoint DrawingML 数学扩展封装的 `a14:m`/OMML 结构；
- 使用现有可验证的 OfficeMath 样本作为结构模板；
- 不把 Word 专用结构直接当作 PowerPoint 结构；
- 维护命名空间、AlternateContent/fallback 和必要的关系；
- 让 `FormulaOfficeMathValidator` 能够统计并解析结果；
- 写入副本而不覆盖输入；
- 对每个写入对象保留源哈希、目标哈希和报告。

## 10. 公式样式策略

### 10.1 角色字号

当前项目基线：

| 角色 | 基准字号 |
|---|---:|
| `inline` | 34 pt |
| `standalone` | 38 pt |
| `core` | 42 pt |

基准值来自 `config/physics-ppt-style.config.json`，不是模型自由生成的字号。公式写入后必须检查边界、基线、相邻对象、换行和裁切；不能为了塞入页面无限缩小。

### 10.2 token 样式

| token | 字体/样式建议 |
|---|---|
| Latin variable | Cambria Math，遵循数学变量斜体 |
| Greek variable | Cambria Math，遵循数学变量样式 |
| Number/operator | Cambria Math，直立/标准运算符 |
| Unit | 直立，不能被误设为变量斜体 |
| Chinese subscript/text | 中文回退字体，直立 |
| Formula color | 新生成公式按项目公式色，已有公式默认保留原色 |

当前候选脚本中的固定 `3800`、全量斜体和单一 Latin 字体必须在 F5 阶段修复后，才可扩大图片公式写回。

## 11. 写回和不可变属性

### 11.1 写回原则

- 输入 PPTX 永不覆盖；
- 每批输出唯一目录和唯一副本；
- 失败项保留原对象或从原对象重跑；
- 尽可能保持原位置、尺寸、旋转、层级和邻接关系；
- 对象类型变化时，必须单独记录 `carrierBefore`/`carrierAfter`；
- 公式替换不能顺手移动、缩放、裁剪或删除其他对象；
- 原始图片媒体和 MathType OLE 不得因写回而丢失；
- 写回报告必须能回答“实际写了什么、什么被跳过、为什么跳过、如何回滚”。

### 11.2 允许的公式专项差异

公式对象从文本/图片变成 OfficeMath 时，允许记录以下明确差异：

```text
carrierBefore -> carrierAfter
formula target representation
formula-specific XML nodes
formula-specific style properties
```

除此之外，页面数量、页面顺序、题干文本、其他对象几何、动画、媒体和关系仍按项目不变量检查。若新公式必须改变边界框才能显示，必须证明是公式对象自身的必要变化，并保留原始边界和视觉证据。

### 11.3 SVG 写回

SVG 写回只适用于 canonical 内容已确认但 OfficeMath 不稳定的对象：

- SVG 只替换或叠加公式区域，不覆盖其他内容；
- 保持透明边距、纵横比和目标边界；
- 输出中明确标记 `FallbackSvg`；
- 不把 SVG 计入 OfficeMath 可编辑数量；
- 失败时恢复原图或原文本框。

## 12. 验收门禁和证据

### 12.1 门禁顺序

```text
G0 规则/配置/schema 校验
  -> G1 载体和源哈希完整
  -> G2 FormulaIR/canonical 内容校验
  -> G3 转换片段 XML 校验
  -> G4 PPTX 副本结构和不变量校验
  -> G5 PowerPoint 打开/保存/导出
  -> G6 PDF/PNG 视觉审查
  -> G7 manifest/summary/回滚证据完整
```

不允许用后面的视觉门禁替代前面的内容门禁，也不允许用 Open XML 通过替代 PowerPoint 实际打开。

### 12.2 独立证据边界

| 证据 | 能证明 | 不能证明 |
|---|---|---|
| OCR/公式模型输出 | 识别候选 | 公式语义正确 |
| 白名单匹配 | canonical 源选择符合策略 | 图片一定对应该白名单项 |
| FormulaIR 校验 | token/规则完整 | 页面实际渲染正常 |
| Open XML 验证 | 包结构和 XML 合法 | PowerPoint 版本兼容、物理语义正确 |
| PowerPoint COM | 宿主可打开、保存、导出 | 投影仪/扩展屏/长时间播放稳定 |
| PNG/PDF 比对 | 外观和几何没有明显回归 | 分式方向、变量含义百分百正确 |
| VLM 二审 | 视觉异常线索 | 独立的语义真值 |

### 12.3 交付证据

每个 `Converted` 或 `FallbackSvg` 对象至少要有：

- 输入文件和对象引用；
- 原始图片/文本哈希；
- 裁剪图或原对象预览；
- 识别器、转换器、模型和权重版本；
- canonical FormulaIR；
- 目标 TeX/MathML/UnicodeMath；
- 目标 OMML/SVG 路径；
- 结构验证结果；
- PowerPoint/PDF/PNG 证据；
- 视觉审查结果；
- 回滚路径和最终决策原因。

## 14. 测试矩阵

### 14.1 单元测试

- 空白、全半角、等号、乘法别名归一；

### 14.2 结构测试

- `a14:m`/OMML 命名空间和封装；
- `m:oMath`、`m:r`、分式、上下标和根式结构；
- 关系部件和媒体不丢失；
- OfficeMath 数量增量与 manifest 一致；
- 失败副本不存在或不列入成功交付；
- 原 PPTX 哈希保持不变。

### 14.3 不变量测试

除已声明公式对象差异外，必须比较：

- 页数和顺序；
- 文本内容；
- 其他对象数量、类型、位置、尺寸、旋转和层级；
- 动画、触发器、切换、速度和计时；

### 14.4 视觉测试

- 公式消失；
- 分式错位或裁切；
- 上下标漂移；
- 中文缺字或字体回退；
- 单位斜体化；

视觉比较必须使用源课件基线，区分源课件既有问题和本次新增问题。

### 14.5 真实样本测试

- 含 MathType OLE 和 OfficeMath 的混合课件；

## 15. 失败、降级和回滚

### 15.1 失败处理

| 失败 | 必须动作 |
|---|---|
| 图片定位失败 | 保留原图，`ManualRequired` |
| 模型不可用 | `CandidateOnly` 或 `OriginalKept` |
| 候选不唯一 | 不写回，`ManualRequired` |
| 白名单未命中 | 不写回，保留候选 |
| FormulaIR 解析失败 | 不写回，报告原始候选 |
| OMML 生成失败 | 尝试 SVG 或保留原图 |
| Open XML 失败 | 删除本批输出，标记 `Failed` |
| PowerPoint 修复/打开失败 | 删除本批输出，保留原对象 |
| 视觉新增 Blocked | 不交付该副本 |
| evidence hash 不匹配 | 禁止复用，重新候选化 |

### 15.2 回滚原则

- 只删除本次批次输出，不使用 `git reset --hard`、`clean` 或覆盖输入；
- 原始 PPTX、原始媒体、MathType OLE 和原始文本始终是回滚源；
- 写入前先生成计划和证据，写入后再更新状态；
- 任何“成功但证据不全”的副本都按失败处理；
- 迁移 MathType 时不能删除原 OLE 作为“清理”步骤。
